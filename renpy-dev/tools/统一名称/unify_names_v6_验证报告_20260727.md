# unify_name_translations.py v6 验证报告

## 日期
2026-07-27

## 改动内容

### Step 2 分类逻辑改为严格模式

**v5 问题**：使用滑动窗口从 CJK 文本中提取候选变体，误报率 ~70%
- "我听说"、"你确定"、"看好了" 等正文短语被误识别为人名变体
- 用户如果直接 `--apply`，会把正文短语替换为人名，造成严重破坏

**v6 改进**：取消滑动窗口猜测，变体只有两种来源：
1. 概率筛选：英文原名出现在中文译文里 → 英文变体（漏翻）
2. 精确匹配：译文含标准译名 → ok
3. 两者都没有 → omitted（附带完整上下文），不猜测

### omitted 条目附带完整上下文

v5 的 omitted 只有一个 count，v6 在 classification JSON 中新增 `omitted_refs` 字段，
每条 omitted 引用都附带 file/line/en_context/cn_text，方便人工或 LLM 审核。

### 清理

- 移除 `_extract_name_candidates()` 和 `_discover_variant()` 函数
- 移除 `stopwords.json` 依赖
- 24 个历史 JSON 文件移至 `tools/cache/unify_names/`
- README.md 更新为 v6 文档

## 结论

v6 严格模式达到目标：
- **零误报**：不会把正文短语误替换为人名
- **审核友好**：43 个 omitted 条目附带完整上下文，一目了然
- **可分享**：用户可以直接 `--apply` 英文变体，omitted 条目留给人工/LLM 处理
