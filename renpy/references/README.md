# references/ — 分场景参考目录的分类契约

本目录是 SKILL.md「参考知识（按场景索引）」指向的知识体。**SKILL.md 是唯一入口，
本 README 是分类与命名规则的唯一出处**。违反下面任一条都会被 `scripts/tests`
拦下（每个参考必须被 SKILL.md 索引；文件名必须合规；写死的数字必须等于现实）。

## 分区轴：按「Agent 在哪个场景会来查」分四区

与 SKILL.md 索引一一对应，四个分区维度单一、互不重叠：

| 分区 | 场景 | 收什么 | 不收什么 |
|------|------|--------|----------|
| 写游戏 / 引擎行为 | 正在写 / 改 `.rpy` | 引擎陷阱、非显性技巧、排版数值、画廊/养成预设、字体与语言联动、创作/剧本转脚本流程、沙盒/线性模式架构范式 | 完整模板与教程——AI 直接写 .rpy，不背模板 |
| 汉化 | 正在汉化 / 质检 / 润色 | 翻译工作流、汉化故障手册、`config.replace_text` 钩子、译文润色、tl 质检、名字栏 | 工作流里已写过的步骤——一个知识只放一处 |
| 玩家侧 / 解锁 | 处理发行版 / 存档 / 解锁 | 解包/存档/汉化/重放工具地图、解锁画廊/CG 补丁 | 一次性的现场排查过程 |
| 排错 / 工程 | 排查崩溃 / 配 SDK / 判工具边界 / 维护 skill | 排错指南、SDK 配置速查、工具通用度分级与写操作风险表、社区经验学习台账 | 单次案件的排查流水 |

## 命名规则

1. 文件名一律 ASCII、小写、只允许 `[a-z0-9_]`（macOS NFD 归一化 + 检索一致性）。
2. 主题名词优先；同族主题命名一致，如翻译族 `translation_workflow` /
   `translation_polish` / `translation_troubleshooting`（原 `hanization_manual`
   不合规，2026-10-23 改名）。
3. **工具对齐例外**：文档只对应一个脚本时，文件名跟着工具走，不改工具名——
   `tl_check.md` ↔ `checks/tl_check.py`、`namebox_translation.md` ↔
   `sync_namebox_translation.py`。
4. **社区惯例例外**：`renpy_gotchas.md` 的 `gotchas` 是业界通用说法，保留。
5. 不缩写、不造词（除非命中上面两条例外）。新增文件先对照这两条例外再定名。

## 维护约定

- 新增参考：写完内容 → 挂进 SKILL.md 索引对应分区 → 跑 `scripts/tests` 回归。
  孤儿（没被索引）、命名不合规都会被测试点名。
- 改动数量/名称：同步 SKILL.md 索引与根 README 的「20 个分场景参考」；数字由
  `test_repo_consistency.py` 自动校（计数不含本 README）。
- 唯一出处纪律：同一知识只在一处写全，reference 之间只做链接不复制正文
  （根 README 约定 #4）。
